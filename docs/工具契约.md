# 只读工具契约

## 统一输入

三个工具都接收：

```json
{
  "user_id": "u_001",
  "order_id": "o_1001",
  "request_id": "tr_xxx"
}
```

`user_id` 只能由系统登录态注入。模型不能覆盖它；`order_id` 为空时仅允许查当前用户最近订单。

## 统一输出

```json
{
  "status": "success",
  "data": {},
  "error_code": null,
  "error_message": null,
  "latency_ms": 12.3,
  "source": "mock_data"
}
```

`status` 枚举为 `success`、`not_found`、`forbidden`、`invalid_argument`、`timeout`、`upstream_error`、`data_incomplete`。

## 工具职责

| 工具 | 读取内容 | 不允许做什么 |
|---|---|---|
| `get_order` | 订单、支付、商品和用户归属 | 修改订单、退款或隐藏权限错误 |
| `get_logistics` | 发货、签收、物流异常 | 改地址、拦截物流 |
| `get_after_sales` | 售后单、重复申请、历史限制 | 创建或关闭售后单 |

## 本地工具清单

当前本地实现位于 `src/customer_agent/tools/local.py` 的 `LocalReadOnlyTools`。三个核心查询都返回相同的 `ToolResult` 结构，并从项目 `data/` 目录加载 JSON 模拟数据：

| 方法 | 数据文件 | 主要行为 |
|---|---|---|
| `get_order(user_id, order_id, request_id)` | `orders.json` | 查询订单并校验归属；未提供订单号时转为当前用户最近订单查询 |
| `list_recent_orders(user_id, request_id)` | `orders.json` | 返回当前用户最近最多 3 笔订单的安全摘要字段，不暴露完整记录 |
| `get_logistics(user_id, order_id, request_id)` | `logistics.json` + `orders.json` | 先校验订单归属，再返回发货、签收和物流事实 |
| `get_after_sales(user_id, order_id, request_id)` | `after_sales.json` + `orders.json` | 先校验订单归属，再返回售后状态、重复申请等事实 |

`list_recent_orders` 是编排层可用的本地工具方法；当前 MCP Server 暴露的协议工具是 `get_order`、`get_logistics`、`get_after_sales`，其中 `get_order` 在 `order_id` 为空时提供最近订单列表能力。

## 什么时候使用 MCP

MCP 是工具的标准化连接协议，不会自动让查询更准确，也不等同于接入真实订单平台。当前 Demo 的 MCP Server 最终仍调用同一批 JSON 模拟数据，主要用于协议与隔离边界的演示。

| 情况 | 建议模式 | 原因 |
|---|---|---|
| 本地开发、规则调试、自动化测试、离线演示 | 本地工具 | 少一个进程和协议往返，配置简单、结果稳定，便于定位问题 |
| 多个 Agent/应用需要复用同一套工具服务 | MCP | 把工具实现与调用方解耦，统一发现工具和交换结构化参数/结果 |
| 工具需要独立部署、使用不同运行时或由另一团队维护 | MCP | 可单独管理服务生命周期、权限和发布版本 |
| 需要比较直接函数调用与协议调用的延迟、失败和可观测性 | MCP + 本地对照 | 使用同一工具契约和案例做受控比较 |
| 生产接入订单或支付写操作 | 先不要据此直接切换 | 仍需平台认证授权、租户隔离、审计、幂等、写操作确认和安全评审；当前工具全部只读 |

配置方式：`MCP_ENABLED=true` 选择 MCP 作为默认工具后端；`false` 使用本地工具。单次 `/chat` 请求可通过 `tool_mode: "mcp"` 或 `tool_mode: "local"` 显式覆盖默认值。MCP Server 默认通过 stdio 子进程启动，也可使用 `MCP_SERVER_COMMAND` 指定命令；本地模式不需要该配置。

例子：本地开发通常保持 `MCP_ENABLED=false`；验证 MCP 路径时设为 `true`，或在请求 JSON 中传入 `"tool_mode":"mcp"`。无论哪种模式，都应检查 trace 中的工具来源、状态和耗时，并验证越权订单不会返回业务数据。
