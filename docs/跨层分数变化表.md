## 指标解读

### 工具路径准确率 54.1% 偏低的原因

这是**过程指标**，不代表答案错误。主要失败模式：

1. **评测集期望的工具序列更精简**：例如评测集期望"仅查 get_order"，但 Agent 实际查了 get_order + get_logistics + get_after_sales（保守策略），结果正确但路径不一致
2. **工具调用时机不同**：Agent 在意图未明确时不调用工具，但评测集标注了期望调用

这说明 Agent 当前的工具调用策略偏保守（宁可多查也不漏查），与评测集期望的最优路径存在差异。这是**可改进的方向，但不是功能性缺陷**。

### 会话状态准确率 60.0% 的主要差距

40 个案例中 16 个最终状态不匹配，主要原因：

- 部分应该进入 `resolved` 的案例停在了 `handoff`（Agent 判断偏保守）
- 部分 `needs_order_id` 状态的案例因订单选择逻辑差异产生偏差

## 下一步提升方向

按影响大小排序：

1. **补齐 5 个 unsupported 工具**（长期记忆写入/召回/删除、商品尺码检索）  
   预期：工具路径准确率计分覆盖率从 74/79 提升到 79/79

2. **优化工具调用策略**（减少不必要的多余调用）  
   预期：工具路径准确率从 54.1% 提升，估计可达 65-70%

3. **优化会话终态判断**（resolved vs handoff 的边界）  
   预期：会话状态准确率从 60% 提升到 70%+

4. **引入真实 LLM** 后重新运行，观察意图识别和槽位准确率的变化  
   预期：意图准确率从 77.2% 提升，但工具路径可观测性降低

## 如何使用这张表

每次新增一层能力后：

```bash
# 运行评测，记录分数
PYTHONPATH=src python3 -m evals.runner \
  --dataset data/multiturn_eval_v1.json \
  --report reports/baseline_v0.json

# 把输出的 summary 数字填入上方表格对应行
```

**没有填入分数的层不算完成。** 这是学习路径的核心纪律之一。
