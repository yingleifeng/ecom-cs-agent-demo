# 数据盘点与表结构

## 1. 数据分层

本 Demo 将数据分成三层：

| 层 | 作用 | 访问方式 | 是否作为退款结论依据 |
|---|---|---|---|
| 用户与订单事实 | 当前用户、订单、商品和支付状态 | 只读工具 | 是 |
| 物流与售后事实 | 发货、签收、售后单和重复申请 | 只读工具 | 是 |
| 政策与客服知识 | 退款规则、商品例外、物流 FAQ、人工规范 | RAG | 提供政策证据，不直接下结论 |

## 2. 表关系

```text
users 1 ──── N orders
orders 1 ─── 1 logistics
orders 1 ─── N after_sales
orders N ─── 1 products
```

`orders.user_id` 是权限校验的关键外键。每次查询必须同时使用系统注入的 `user_id` 和用户提供的 `order_id`。

## 3. 字段字典

### users

| 字段 | 类型 | 含义 | 展示规则 |
|---|---|---|---|
| `user_id` | string | 用户唯一标识 | 内部关联，可在调试面板展示 |
| `display_name` | string | 脱敏展示名 | 可展示 |

### products

| 字段 | 类型 | 含义 | 展示规则 |
|---|---|---|---|
| `product_id` | string | 商品唯一标识 | 内部 |
| `product_name` | string | 商品名称 | 可展示 |
| `category` | enum | 普通实物/定制商品/特殊商品 | 可展示 |
| `special_type` | enum/null | `custom`、`perishable`、`intimate` 或空 | 可展示判定，不展示内部标签 |
| `refund_auto_rule` | enum | `normal`、`manual_review`、`excluded` | 仅规则层使用 |

### orders

| 字段 | 类型 | 含义 | 是否为资格必需字段 |
|---|---|---|---|
| `order_id` | string | 订单号 | 是 |
| `user_id` | string | 订单所属用户 | 是，权限校验 |
| `product_id` | string | 商品外键 | 是 |
| `payment_status` | enum | `paid` / `unpaid` / `refunded` | 是 |
| `order_status` | enum | `unshipped` / `shipped` / `delivered` / `cancelled` | 是 |
| `product_name` | string | 冗余展示字段 | 否 |
| `category` | string | 商品类目快照 | 是 |
| `special_type` | string/null | 下单时的特殊商品属性快照 | 是 |
| `ordered_at` | datetime | 下单时间 | 否 |

### logistics

| 字段 | 类型 | 含义 | 是否为资格必需字段 |
|---|---|---|---|
| `order_id` | string | 订单外键 | 是 |
| `shipped_at` | datetime/null | 发货时间 | 未发货判断必需 |
| `logistics_status` | enum | `not_shipped` / `in_transit` / `delivered` / `exception` | 是 |
| `last_updated_at` | datetime | 最近物流更新时间 | 异常解释使用 |
| `signed` | boolean | 是否签收 | 已发货判断必需 |
| `exception` | boolean | 是否物流异常 | 已发货判断必需 |

### after_sales

| 字段 | 类型 | 含义 | 是否为资格必需字段 |
|---|---|---|---|
| `order_id` | string | 订单外键 | 是 |
| `has_active_case` | boolean | 是否存在进行中的售后单 | 是 |
| `case_type` | string/null | 售后类型 | 解释使用 |
| `case_status` | string/null | 售后状态 | 解释使用 |
| `duplicate_request` | boolean | 是否重复申请 | 是 |
| `history_restriction` | boolean | 是否存在历史限制 | 风险审核使用 |

## 4. 数据完整性规则

- 同一 `order_id` 在订单、物流和售后数据中最多对应一条当前快照。
- `orders.user_id` 不匹配当前登录用户时返回 `forbidden`，不得返回订单字段。
- 订单、物流、售后任一关键记录缺失时返回 `data_incomplete`，不能下肯定退款结论。
- `order_status=unshipped` 时 `logistics_status` 应为 `not_shipped`；冲突数据用于测试降级。
- 业务表保存事实，退款资格由规则函数计算，不在数据中预写 `eligible`。

## 5. 当前数据规模

Ticket 02 先使用 4 个用户样例和 4 个订单样例跑通主链路。本阶段扩展目标为 20-30 个用户、40-60 个订单，并覆盖正常、特殊商品、未支付、已有售后、重复申请、越权、缺失和冲突数据。
